## 3. Brief

Keep reusable rules in a shared file the child reads first (ViQSilent: `estudios/cen_2608/referencia/v5/completa/encargos/comun.md`)
and one file per task (`encargos/<tarea>.md`). The `task` text stays short: preparation (`git merge --ff-only <commit>`,
`git checkout -b <branch>` — new name if the branch exists), the two files to read, a 2-line summary, the exit reminder.

Every task file has: traspaso (exact paths, lines, numbers, what earlier children found and ruled out), what to do,
acceptance with numeric thresholds and the exact commands, its own data folder (`paso_vNN/`), branch name, time cap, and
what is out of scope (name the other children's areas so they don't collide).

Exit schema: STATUS / FILES_MODIFIED / COMMITS / VERIFICATION / KEY_FINDINGS (<300 words, no code or logs).

## 4. Launch and monitor

- `isolation: "worktree"` per child; worktrees start at the parent checkout, hence the ff-merge step.
- Record the start time (A/B: `E/ab_modelos.md`).
- Do not poll. Completion wakes the orchestrator. If the user asks how a child is doing: `tail` its `bitacora.md`; if
  silent, `t3_thread_read` view=activity, `afterPosition` = itemCount−12, `maxCharsPerItem` ≈300.
- Switching a child's model is cheap only before it has real work: cancel, then relaunch with a new branch name and the
  same data folder.
- Machine: 10 cores, 16 GB. Each heavy run (`medir_t0`, `validar_10ms`) uses ~1 core for 10–15 min of init; 4 children in
  parallel is fine. Don't `kill` by folder pattern (hit another child once).

## 6. Lessons (dated; add new ones on top)

- 2026-11-11: Claude children (Opus too) end their turn while their own background jobs run, and the platform reports "completed". Put "do not end your turn with background processes; wait in the foreground" in every brief, and check the branch/log before trusting a "completed".

- 2026-11-11 (Theo, x.com/theo/status/2119960608816988596, 1.1M proxied requests): on Claude Ultra ($200/mo) a month of only Opus 5.5 ≈ $14,662 at API prices; Fable 5.2 only ≈ $3,021 (Fable capped at 50 % of each weekly limit, shared with Opus: Fable first leaves $7,331 of Opus). So 1 $ of Fable costs ~2.4 $ of Opus capacity. Use Fable for short, high-leverage design/review turns; implementation loops on Opus/Sonnet/DeepSeek.

- 2026-11-11: Before sending a child's "read-only" PF script to the bridge, grep it for `Execute`: running the case's own ComInc deletes events with `p_from`. Run a temporary copy pointed at an empty IntEvt, deleted in finally. And a "why is X slow" diagnosis brief should ask for time by verdict (accepted/rejected), not just by phase: that split was the key finding.

- 2026-11-11: PF scripts I write for the bridge: check every object they assume exists (temp commands get deleted by cleanup scripts), create/delete temp objects inside try/finally, and never set ElmRes attributes P2 did not set (`calTp`): a mis-typed ElmRes makes PF silently write into the case's own Result_All. Tell mechanical children "do not end your turn until the result is in".

- 2026-11-11: when two parallel children touch the same function, check for SEMANTIC conflicts at merge, not only textual ones: a memo/cache added by one (keyed by name) silently becomes wrong when the other makes the cached value depend on extra inputs. And launch long children on the newest base: a pre-speedup base multiplies every test run.

- 2026-11-11: hand-off between models works: Fable left a harness + bitácora + an ideas file (I extracted from its reasoning), and DeepSeek continued in a new branch from its HEAD without redoing anything. When cancelling a strong-but-expensive child, mine its activity for ideas and pass them on. Also: a Codex child that hit the quota resumes by itself when the quota resets — cancel it if the work was handed to someone else.

- 2026-11-10: Fable 5.2 high on the Claude subscription burned the window in ~20 min of a heavy task. For multi-hour children, the subscription is not a free lunch; a rate-limited Claude child resumes by itself when the window resets, so do not relaunch or switch model; just wait for its notification.

- 2026-11-10: Codex quota can run out mid-session with no warning (Astra died at launch). Before a long Codex child, consider the remaining quota; if it fails at once, check for a branch/folder before relaunching, and do not switch model unasked.

- 11-10: Fresh worktrees lack untracked test data (proofs/, salida_* captures): when merging, symlink missing files one by one from the live worktree (ln -s into an existing dir nests the link — link files, not dirs). Children report '27 skipped' for the same reason.
- 11-10: Running a flow child and a dynamics child in parallel saves time, but the dynamics child's failure may be inherited from the stale flow; re-run on the integration before diagnosing.

- 11-10: When PF hides an enum's text (PF 2024 API), verify the semantics by checking the documented equation against PF's own results (P3 did it to 1e-8). Model-input pointers found in a probe (e.g. cpCtrlNode) are legitimate production inputs under raw-only; results (m:/c:) are not.

- 11-10: PF traps for bridge briefs: (1) pointing ComInc at an IntEvt whose events have `p_from` (left by a DSL in a past run) makes PF DELETE them at init → always run on a COPY of the event folder with p_from=None; (2) ComSim.cominc resolves to the first ComInc in the case folder, so a ComInc copy silently redirects the user's Run Simulation → put copies in a subfolder or delete them at the end; (3) a run B identical to run A is a red flag worth a check, as this child did.

- 11-10: When porting PF scripts across versions, have the child probe the API surface first and measure coverage against a reference attribute list; it turned an unknown into a 19-minute run. Event folders can be nested under the case: extractors must walk IntEvt a few levels (bounded BFS), not GetContents of one level.

- 11-10: Before chasing a 'PF tolerance' explanation for a ppm gap, sweep errlf on a COPY of the ComLdf: a converged Newton is insensitive (0 ppm over 0.01–50 MVA), which closes the hypothesis in one cheap run. Read option flags (iopt_tem) before reading their values (temperature).

- 2026-11-10: PF 2024 SP4 lacks `app.GetAvailableAttributesAsJson` (PF 2025 has it); extractor briefs for 2024 need a compat function and a coverage check against a known attribute list.
- 2026-11-10: PF's ElmRes t=0 row is the ComInc initial point (after t=0 switching, e.g. a TSC stage), NOT the ComLdf load flow. Say so explicitly in briefs and give the ComLdf source when 'flow' values matter; two children (L, M) built conclusions on that confusion.
- 2026-11-10: PF bridge briefs: ComInc resets ComSim.tstop (set tstop AFTER ComInc), and AddVariable returns 0 even for nonexistent names (validate with a 2-step run + FindColumn). PF's RMS time grid is not uniform after internal events: align by time, not index.
- 2026-11-10: a 'gain gap' from medians of secants (ΔQ/ΔU with tiny ΔU) can be pure artefact; ask children to compare per-element ratios/regression and sums before chasing a model fix. And when a child touches an enum→value mapping, review every enum branch: J fixed one case and silently broke another.
- 2026-11-10: a child's 'estimated' cost breakdown (E: residual ≈500 s) turned out 10× off in the next child's measurement. Brief speed work on profiled numbers (cProfile/counters), never on estimates.
- 2026-11-09: 'PF passed, we fail' turned out false: PF hits max iterations nearly every step and continues. Before briefing a convergence fix, read PF's ComSim log for 'No convergence' warnings and parity of warning counts.
- 2026-11-09: DeepSeek child A ended its turn "still waiting for the diagnostic run" with the run alive in the background → reported `completed` with no result. Brief rule: never end the turn waiting on a run; wait in the foreground (sleep 60 + `ps -p` loop, ≤9 min per call). On such a completion, check `ps` + bitácora and resume via `t3_thread_send` on the child thread.
- 2026-11-06: An async child that has to wait for a long external job (PF run, bridge command) will end its turn with 'I'll keep checking' and never come back: nobody wakes it. Put the wait inside the turn: give it a blocking wait command (loop with sleep, ≤ its terminal timeout) and say explicitly 'do NOT end your turn while waiting; ending it = abandoning the task; repeat the blocking command until done or until <hour>'. Or split launch and wait/upload into two children.

- 2026-11-06: Any cache or memo a child adds (init point, compiled library, Jacobian template) must key on every input that changes the answer. Bit-identity gates on one fixed case cannot see a stale-cache bug. Require in the brief a test that changes one input (a parameter, not just the state) after a first call and gets a different answer, and read the cache key yourself at merge.

- 2026-11-06: Two children that are each bit-identical can still break parity when merged. The C backend returned views of a reused buffer, and the other child's Jacobian code re-read the first evaluation after later ones had overwritten it. Always rerun the bit-identity gate on the merge itself, never infer it from the parents. When a fast path returns buffers it owns, say so in the brief ("returned arrays are only valid until the next call").

- 2026-11-06: For speed work, gate the new path behind an env flag and demand bit-identical parity at three levels (per-instance evals, assembled F/J, the 10 ms PF comparison). The child then reports the honest split (what went native, what fell back and why) and the merge is risk-free; the speedup you get is bounded by what stays in Python, so ask for that breakdown in the brief.
